# ADR-0004：对象存储安全准入暂停与候选评估

- 状态：Accepted
- 日期：2026-09-06
- 决策者：项目用户确认，实施代理记录
- 关联任务：M01.1
- 取代：无（不直接改写历史技术基线或 ADR-0001）
- 被取代：无

## 背景

启动 M01.1 时，官方 MinIO 公告 GHSA-hv4r-mvr4-25vw 显示基线 `RELEASE.2025-04-22T22-12-26Z` 在高危认证绕过影响范围内。2026-09-06 用户明确选择“先评估受维护的 S3 兼容替代方案，再启动知识存储”。这不是授权部署商业 AIStor、接受新许可或直接替换 KF 核心。

## 决策驱动因素

- 执行“没有未处置高危漏洞”的基线，而不是机械执行失效的旧版本建议。
- 不改变原 KF 运行项目、源 ZIP、启动 TAR、检索核心和 Milvus 2.5 兼容目标。
- 在同一卡内继续完成可独立验证的部分，不因局部风险放宽安全门槛。
- 不把“仅本地/隔离部署”写成漏洞已修复，不默认为用户接受风险。

## 决策

1. 当前可执行 Compose 仅包含 MySQL 8.4.11、Redis 8.2.6、etcd 3.5.18；独立 project/卷/内部网络和随机凭据，MySQL/Redis 另接专属访问桥，仅 loopback 发布宿主端口；etcd 不发布端口。本机 internal-only 网络实测没有宿主映射，因此不以容器 healthy 代替连接验证。
2. 不提供旧 MinIO 或 Milvus 可执行 profile。Compose profile 可被显式指定服务启用，不能作为安全禁用机制。
3. 新对象存储和 Milvus 暂不启动，M01.1 为 IN_PROGRESS；不得推进 M01.2 或宣称五服务完整通过。
4. 优先评估 SeaweedFS，Garage 备选，RustFS 观察；候选不等于选型生效。精确版本安全与兼容证据、许可确认和后续采用 ADR 完成后才能替换。
5. 保留 `Milvus 2.5.15 + PyMilvus 2.5.18` 验证目标。替换只改变 S3 适配/部署配置，不改变 KF 检索逻辑。

## 备选方案

- 继续部署旧 MinIO：用户未选择，且存在高危准入问题，不执行。
- 直接升级商业 AIStor：涉及新分发、许可与运维决策，未获授权，不执行。
- 立即替换其他 S3 产品：没有本项目版本组合的验证证据，只开展评估。

## 结果与影响

先完成三服务增量，对象存储和向量库延后。历史流程图 MinIO 节点代表原目标，不再是当前已批准运行组件；新组件确定后再同步图，不提前把 SeaweedFS 画成已采用。

## 安全与数据影响

不写入旧业务/知识数据，不连接旧网络。新服务仅用合成探针。原 KF 仍运行且未修改；其现有 MinIO 安全问题另行提示，不能擅自停止或升级。

本次直接暂停依据是 [认证绕过公告](https://github.com/minio/minio/security/advisories/GHSA-hv4r-mvr4-25vw)。另一条 [GHSA-xh8f-g2qw-gcm7](https://github.com/minio/minio/security/advisories/GHSA-xh8f-g2qw-gcm7) 明确单节点 standalone 不注册相关路由，不能误写为本计划的实际可利用漏洞。官方社区仓库显示已归档，见 [维护页](https://github.com/minio/minio)。

## 运维与回滚

只停止新 project 精确容器，不删卷，不改旧 KF。对象存储没有新运行资产，无数据迁移/回滚操作。本 ADR 不接受候选产品条款，不取消安全准入。

## 验证方式

三服务经过静态正反测试、真实健康/认证/读写、GitHub CI；候选按 [评估清单](../operations/s3-alternative-evaluation.md) 验证。只有补齐 S3/Milvus 真实验收并推送完成记录，M01.1 才能 DONE。
