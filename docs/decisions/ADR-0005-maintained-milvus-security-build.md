# ADR-0005：新平台自维护 Milvus 安全构建

- 状态：Accepted
- 日期：2026-09-07
- 决策者：项目用户确认，实施代理记录
- 关联任务：M01.1
- 取代：ADR-0004 第 5 项中的 Milvus 2.5.15 验证目标
- 被取代：无

## 背景

对象存储候选已有可复现的安全派生构建，但 Milvus 官方稳定镜像尚不能通过项目“无未处置 HIGH/CRITICAL”门禁。Milvus 2.5.27 虽修复已公开的产品认证绕过，完整扫描仍有 3 CRITICAL/51 HIGH 包实例；2.6.23 为签名发布提交 `bfa1bc34f93df2ccd20fa7c060463c6c6812d355`，仍有 2 CRITICAL/78 HIGH 包实例，均位于两个 Go 二进制中。

其中 `google.golang.org/grpc` 1.79.3 受 CVE-2026-84304 影响。该问题发生在认证前的 HTTP/2 数据接收阶段，私网和 Milvus 密码不能视为修复。用户于 2026-09-07 明确同意新平台自建并维护安全修补版 Milvus。

## 决策驱动因素

- 满足项目已接受的 HIGH/CRITICAL 安全门禁。
- 保留 KF 依赖的 Milvus 接口与数据能力，不改变 KF 核心业务。
- 固定源码、工具链、补丁和扫描证据，能够审计和重复验证。
- 官方发行重新满足门禁后能够退出自维护分叉。

## 决策

1. 新平台以 Milvus v2.6.23 签名提交为功能基线，生成自维护派生镜像；不改原 KF 源码、容器、数据或其检索业务逻辑。
2. 第一批依赖修补至少包含 Go 1.27.1、gRPC-Go 1.83.1，以及当前报告中有修复版本的 `x/net`、`x/text`、`x/crypto` 和 OpenTelemetry。最终范围以完整复扫结果为准，不能只修一条公告。
3. 构建器、运行基线、源归档、模块锁和补丁都必须固定摘要；主二进制和 `libmilvus-planparser.so` 必须由同一修补依赖集构建并分别核查。
4. 候选只有同时通过构建来源校验、HIGH/CRITICAL 完整扫描、版本/依赖检查、认证负向、S3 兼容、向量写入检索、重启持久化和资源边界后，才能进入 Compose。
5. 构建失败、扫描失败、证据过期或兼容失败均保持 M01.1 `IN_PROGRESS`。不得通过忽略文件、仅隔离网络或“未观察到攻击”降级门禁。
6. 镜像只在新平台本地和项目 CI 构建验证，当前不发布公共镜像。以后若分发，必须补齐第三方许可证、SBOM、签名和发布权限评审。

## 备选方案

- 继续使用官方 2.5.27/2.6.23：不能满足已接受的安全基线，不采用。
- 等待下一官方版本：可降低维护成本，但发布日期和修补范围不确定；保留为后续退出自维护构建的优先路径。
- 仅用反向代理或内网隔离：可降低暴露面，但不能修复认证前资源耗尽，不作为准入依据。
- 更换向量数据库：会改变 KF 兼容边界和后续架构，当前不扩大到此方案。

## 结果与影响

项目新增 Milvus 安全派生配方、依赖补丁、构建/扫描证据和兼容回归。每次上游 Milvus、Go 或安全公告变化都要重建复扫；官方版本满足门禁后优先回归官方发行，减少长期分叉。

该决定增加构建时长和 CI 成本。Milvus 官方构建建议至少 8 GB 内存、50 GB 可用空间；实际构建使用独立缓存，不复用原 KF 卷。不能将本 ADR 写成构建已经完成或生产安全认证。

## 安全与数据影响

修补候选不得读取旧 KF 密钥或数据，只使用新平台随机凭据和合成验收数据。认证、端口和资源限制仍由后续 Compose 负责，安全镜像本身不等于安全部署。漏洞扫描中不可利用或无修复项也必须保留适用性判断，不能删除证据。

## 运维与回滚

候选尚未接入 Compose 时，只废弃本地派生 tag 和证据，不影响任何服务。接入后回滚必须先验证同一数据格式与元数据兼容，只替换新平台精确容器且不删除卷；不得把数据回滚到原 KF。

## 验证方式

- [gRPC-Go CVE-2026-84304](https://github.com/grpc/grpc-go/security/advisories/GHSA-vp52-pcj8-j9qc)
- [Milvus v2.6.23 发布](https://github.com/milvus-io/milvus/releases/tag/v2.6.23)
- [Milvus 官方 Docker 构建说明](https://github.com/milvus-io/milvus/blob/v2.6.23/build/README.md)
- 后续构建、扫描和契约结果记录在 `docs/testing/`，本 ADR 只确认方向和边界。
