# ADR-0008：M01 gRPC 安全维护与隔离兼容验证

- 状态：Accepted
- 日期：2026-09-09
- 决策者：用户授权插入 M01 基础镜像安全修补与兼容性验证
- 关联任务：M01 安全维护、M02.2 验收恢复
- 取代：ADR-0005 中 grpc 1.83.1 的固定修补目标
- 被取代：无

## 背景

远端运行 34323363851 在 etcd 与 SeaweedFS 检出 CVE-2026-84445；Milvus 模块锁也包含 grpc 1.83.1。
扫描命中依赖版本，不代表已证明当前 xDS 路径可利用；仍按既定无 HIGH/CRITICAL 门禁处理，不使用忽略规则。

## 决策驱动因素

- 保持原产品版本、存储格式、KF 核心与既有数据卷不变。
- 仅修补所需依赖，验证全部二进制/完整镜像和真实 S3/向量兼容性。
- 新缓存、报告与下载位于 F 盘项目内；不迁移已有 Docker 数据。

## 决策

1. etcd 3.6.14 与 Milvus 2.6.23 功能源码不变，grpc 由 1.83.1 升至已修补的 1.83.2。
2. SeaweedFS 4.45 已依赖 1.85.0-dev；先核验同线已修补的固定伪版本 v1.85.0-dev.0.20260825072537-93e31b48545e，避免无验证强制降级到旧接口线。全量构建/扫描/兼容失败则不采用。
3. 候选单独编号 .2，旧镜像保留；先隔离合成数据验证，不把正在运行的容器当首次试验对象。
4. Milvus 主程序和 planparser 动态库均由同一模块锁构建，分别检查，不只替换主程序。
5. 通过后才能更新新平台镜像锁；是否切换运行实例按已验证的持久化/回退方案执行，绝不删卷、改旧 KF 或推进 M02.3。

## 备选方案

- 忽略漏洞或仅靠内网隔离：违反既定门禁，不采用。
- 全部升级最新产品：扩大存储/接口变化，不采用。
- SeaweedFS 强制替换为 grpc 1.83.2：可能与既有较新依赖接口冲突，不作为未经验证的默认方案。

## 结果与影响

候选构建与回归会消耗时间和空间，尤其 Milvus 包含 C++/Go/Rust；可复用现有构建缓存但不降低验证范围。
通过前台账保持维护进行中，旧的 0 HIGH/CRITICAL 报告仅为历史结果，不代表当前复扫结论。

## 安全与数据影响

候选只使用独立 project、随机凭据、独立端口/卷和合成数据。现有 Docker 卷/原 KF 不迁移、不删除。
任何环境归属、资源预算、编译、扫描或兼容失败必须显式保留，不悄悄改版本或关闭安全门禁。

## 运维与回滚

候选未部署时不影响当前服务；已有运行实例只在候选准入后处理。保留旧摘要与原卷，不自动回退到已知有漏洞镜像作为最终交付。

## 验证方式

来源与模块哈希、完整镜像 Trivy HIGH/CRITICAL、Milvus 双制品依赖、认证负向、S3/向量读写检索、重启与重建持久化、M02 MySQL/HTTP 回归和 GitHub 门禁。
参考 [官方公告](https://github.com/grpc/grpc-go/security/advisories/GHSA-2v4p-qf9q-27wj)、[稳定修补版](https://github.com/grpc/grpc-go/releases/tag/v1.83.2)。
