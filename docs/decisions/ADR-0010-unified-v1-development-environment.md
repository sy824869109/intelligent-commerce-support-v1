# ADR-0010：统一 V1 开发环境与集中验收

- 状态：Accepted
- 日期：2026-09-13

## 背景

用户要求环境集中准备、业务逐步教学；明确使用已有的 `intelligent-commerce-support-v1` Conda 环境，不再新建环境。前端明确使用 Vue 3；模型采用本地 Embedding/重排与云端 LLM。

## 决策驱动因素

避免教学阶段不断切换解释器；保护原 KF、原项目、现有 Docker 数据和其他 Conda 环境；本机 32 GiB 内存、约 12 GiB 显存，项目盘空间有限。

## 决策

1. 本机开发统一到 `F:/heima/ai/python/day01/Anaconda/envs/intelligent-commerce-support-v1/python.exe`。平台、RAG、基础设施客户端和测试工具共同求解哈希锁；不能依次强制覆盖彼此不兼容的版本。
2. 下载、缓存、模型、环境配置、检查报告及新增监控数据留在项目 `_local_artifacts`。Conda 环境本体遵从用户最新要求，留在已有 Anaconda 的 V1 路径，不再要求位于项目依赖目录。
3. 新建的空 `knowledge` Conda 环境已移除；历史 `platform` 环境不再作为默认解释器，保留但不删除；不触碰其他环境。
4. Vue 3 工具链独立于 Conda，放在项目内；当前只创建工具链验证夹具，不实现 M14 页面。
5. 维持 KF 的查询准备、路由、FAQ/文档、稠密/BM25、重排、生成、引用分层。安全必要依赖调整只影响新项目，不修改 KF 源码、环境或压缩包。依赖兼容测试不能替代 M09 Golden Set。
6. 旧 KF 依赖扫描出现已知漏洞，按修复边界选择 LangChain 1.3.9/Core 1.4.6、Transformers 5.10.1、Sentence Transformers 6.0.1、PyTorch CPU 2.13.0 等候选。实际精确版本以统一锁为准。5.10.0 被上游撤回，不采用。
7. Ragas 0.3.6 及其 diskcache 依赖存在未解决审计记录，不进入在线环境。现有 pytest 与合成夹具提供评测开发基础；后续评测指标实现和受维护 Ragas 替代评估仍属于业务阶段，不声称已完成。
8. 监控与入口使用独立 `ics-v1-tools` 分组，避免修改已审查的五存储服务边界。所有端口默认回环，TLS 使用项目本地证书，不修改系统信任库或防火墙。
9. 2026-09-13 用户补充：不要求最新版，但必须较新且稳定。优先选择仍受上游维护的稳定分支或 LTS 的安全补丁版本；不采用 alpha、beta、RC、nightly、开发快照或已停止维护的旧版。版本新旧不能替代漏洞审查和真实兼容测试；已通过验收的组合不因出现新版本而自动升级。
10. 候选镜像扫描与正式准入报告分开保存。候选通过不代表整组环境通过；修补后的自建制品必须记录基础镜像、源码/依赖补丁及身份，再执行完整扫描和真实联测，不能沿用官方版本的稳定性标签替代验收。

### 稳定分支评估依据

- [Prometheus 官方 LTS 周期](https://prometheus.io/docs/introduction/release-cycle/)：核验时 3.13 是受支持分支，支持截至 2027-07-31，因此评估 3.13.3 LTS，而非只检查最新功能分支。
- [Grafana 官方升级与维护策略](https://grafana.com/docs/grafana/latest/upgrade-guide/when-to-upgrade/)：区分主版本、次版本和安全补丁，评估仍受维护的 12.4.10；不把“比 13.x 旧”直接等同于“过时”，也不把它未经验证地称为已安全可用。
- 本轮候选结果、未通过项及本地报告位置见 [环境说明](../operations/v1-environment-guide.md)。上述候选尚未替换正式运行镜像，不修改 KF 核心架构。

## 备选方案

- 平台与 RAG 两个 Conda 环境：隔离更强，但用户明确拒绝，本机不采用。
- 关闭 Windows 智能应用控制：不采用。通过来源校验、官方兼容发行包或管理员支持的信任配置处理，不私自关闭系统防护。
- 增加 Kafka、图数据库、Agent 平台：超出 V1 环境范围，不安装。

## 结果与影响

后续教程统一使用一个解释器。发布时的服务进程和容器边界仍独立于开发解释器选择；统一依赖增加回归范围，任何改动必须检查业务、RAG 和基础设施客户端。新增模型采用 CPU 基线，不预装 CUDA 工具包，不改驱动；GPU 加速需额外兼容性证明。

## 安全与数据影响

扫描须检查跳过项：PyTorch 的 `+cpu` 版本还需核对对应公开版本公告，不能把“被跳过”算零漏洞。下载锁、文件哈希、操作系统签名信任和模型效果是四件不同的事。Windows 拦截会导致模型运行验收失败，不能用导入替身、关闭防护或改名绕过。

云端密钥仅在项目忽略配置中由用户私密填写。未配置或未真实调用必须显示 PENDING；不会发送原 KF 数据。新环境探针只使用合成文本和专属临时集合。

## 运维与回滚

不做 Docker 全局清理，不迁移既有 Docker 数据，不删除历史平台数据。新监控数据放项目目录。失败下载保留断点，不激活哈希不符的文件。旧环境保留不代表可以跳过依赖回归直接恢复运行；通过 Git 对比锁文件后重新验证。

## 验证方式

统一解释器的 pip check、既有 90 项后端及契约/MySQL 回归、Vue 构建和真实 Chromium、依赖审计、模型哈希与推理、LangChain/Milvus 混合检索、指标/追踪/日志写入查询及 TLS 入口检查。逐项结果见环境验收报告；未完成项不得改为 PASS。
