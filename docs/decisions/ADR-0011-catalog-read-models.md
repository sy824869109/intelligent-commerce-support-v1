# ADR-0011：商品与库存读模型边界

- 状态：Accepted
- 日期：2026-09-13
- 关联任务：M04.1

## 背景

环境与 M03 已完成，开始商品业务。当前任务仅建立商品、SKU、类目、属性、价格、库存读模型，不提前实现 M04.2 查询 API 或 M04.3 同步。

## 决策驱动因素

商品事实必须属于 Commerce，不能由 LLM 或 RAG 编造。不同店铺可能使用相同的外部编号；价格和库存的数据源、更新频率不同；未知、过期、缺货需要区分。

## 决策

1. 六类不可变值对象置于 `packages/domain/ics_domain/catalog.py`，只用 Python 标准库，不依赖 SQLAlchemy、Pydantic 或 LangChain。
2. 物理映射置于 `ics_persistence/commerce_schema.py`，延续单库共享迁移机制；Commerce 拥有读模型及后续唯一写入端口，Gateway 不直接操作这些表。
3. 新增六张 `commerce_` 表。主键、唯一 SKU 编码、外键均包含 `tenant_id`；不假定外部编号跨租户全局唯一。身份表仅被外键引用，不改变权限种子。
4. 价格以 `BIGINT minor_units + currency` 表达，沿用 Money 合同的 0 至 9007199254740991 上限；不使用 float、不默认为 CNY。三个大写字母是编码形状校验，不是币种目录或汇率支持承诺。
5. 价格表保存每个 SKU 的一条当前价格读快照，包含左闭右开生效窗口，不承担会员价、优惠叠加、历史价格账本或支付结算。无价格行表示尚无价格事实，不能补成 0。
6. 库存表只保存上游可售量，NULL 表示上游未知，0 表示明确缺货；整行缺失表示未获得快照。本轮不管理仓库账本、预留、扣减或超卖控制。
7. 各表独立携带 source、source_version、as_of、synced_at。版本只能在同一来源内比较，接收时间不能替代来源时间。领域层要求带时区 UTC；数据库存无时区 UTC 的 DATETIME(6)，保留微秒。SQL 适配层的时间转换与新鲜度策略在后续查询/同步实现。
8. 商品与 SKU 状态分别显式记录 DRAFT、ON_SALE、OFF_SHELF、DISCONTINUED。展示资格需同时核对两者，不能只看 SKU；本轮只建模型，不假装已实现可售性判定接口。
9. SKU 规格在领域模型中使用不可变键值元组，拒绝重名键和可变容器；SQL 用 JSON。全类目环检测、跨 SKU 规格组合冲突和乱序覆盖控制由 M04.3/M04.4 完成，不把数据库外键当成这些业务规则。

## 备选方案

把价格库存直接塞进商品 JSON 会混淆规格与更新时间，不采用。建立完整交易、仓库和促销系统超出当前只读客服任务，不采用。金额采用整数最小单位以匹配既有合同，而非另开浮点金额协议。

## 结果与影响

M04.1 完成后仍无商品 HTTP 接口，没有业务同步任务。数据模型为 M04.2 提供明确输入；届时必须从 M03 可信身份取得租户，不能信任前端传来的 tenant_id。复合外键只能防止错误关联，不提供数据库行级读取授权。

## 安全与数据影响

迁移 `m04_0004` 仅新增六张空表，不植入账号或商品，不写原 KF。描述和属性仍是不可信文本，前端转义、RAG 注入防护和公开字段投影不得省略。测试商品仅在临时库和内存示例中存在。

## 运维与回滚

通过显式迁移升级，网关启动不自动建表。MySQL DDL 非原子；失败保留现场，禁止自动删表或跳过版本。降级在第一条破坏性 DDL 前检查商品、身份及平台数据，非空拒绝。已产生业务数据后的回滚需要备份和专门迁移，不执行生产删库。本轮只在临时库演练空库往返。

## 验证方式

纯模型边界测试；真实 MySQL 旧 M03 数据升级保留、全量 metadata 对比、空库往返、租户复合外键、SKU 唯一性、CHECK 精确错误号、金额与微秒往返、未知库存和非空拒绝降级；既有后端、契约、基础 CI 与安全检查回归。
