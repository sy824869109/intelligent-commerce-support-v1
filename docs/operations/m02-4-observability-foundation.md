日期：2026-09-10。状态：IN_PROGRESS；本批是可复用基础函数，不是完整观测平台。

## 已实现与边界

| 内容 | 实现 | 限制 |
|---|---|---|
| Trace | ContextVar + 上下文管理器，生成本地 trace_id，退出/异常恢复 | 不是 W3C traceparent、OpenTelemetry span 或跨进程传播；未接入网关 |
| 诊断日志 | 固定事件/结果白名单，输出 JSON，自动关联当前 request/trace | 不接收自由文本、请求体、异常字符串或任意 attributes；未配置日志存储 |
| Metric | 每实例最多 64 个静态操作名 × 3 种结果，7 个固定延迟区间，锁保护更新 | 内存计数，重启丢失；无 exporter、抓取端口或告警 |
| Audit | 固定字段、动作/结果白名单、引用格式检查、UTC 序列化 | 无持久化、事务保证、防篡改、保留策略或访问控制；不是已写审计 |

流程：调用方进入 trace_scope → 基础函数读取当前上下文 → 返回结构化诊断文本 / 更新有界指标 → 调用方退出时恢复上下文。AuditRecord 单独由可信服务端构造，序列化不代表写入成功。

指标区间为 <=10、(10,50]、(50,100]、(100,500]、(500,1000]、(1000,5000]、>5000 毫秒，属于非累积桶。它们是分布统计边界，不是承诺的 SLO。不能用客户、订单、请求 ID 动态注册指标操作名。

审计引用必须由服务端解析为内部标识，不能用姓名、手机号或客户端自报身份；格式合法不能证明身份可信，也不是自动脱敏算法。当前动作仅 ACCESS_CHECK、COMMAND_SUBMIT、KNOWLEDGE_PUBLISH、TICKET_ASSIGN；未来扩展需要显式评审。保留的引用本身仍有隐私/访问控制要求。
