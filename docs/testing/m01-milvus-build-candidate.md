## 已核实的问题与处理

1. 内嵌 etcd 3.5.23 使用旧 `otelgrpc` 拦截器；传递依赖将模块提升至 0.61.0 后不再提供该接口。候选使用显式 `replace` 固定实际实现到 0.60.0。Windows 对 etcd `api/v3rpc` 的只编译验证通过，不等于 Linux 完整构建或运行测试通过。两个最终 Go 制品还须分别检查实际模块替换记录，安全性由完整复扫确认。
2. `build-cpp` 和 `build-go` 必须顺序执行，避免 Go 链接早于原生库及 pkg-config 文件生成。
3. `scripts/core_build.sh` 显式执行 `make -j ${jobs}`；必须设置小写 `jobs=2`，仅设置 `MAKEFLAGS` 不足以限制它。候选还分别限制 Go、Rust、Conan 和 CMake 并发，顶层 Make 使用单路执行。
4. 先前构建遇到 Docker RPC EOF 和引擎无响应。资源压力是可能原因，尚无证据认定 OOM。用户授权恢复 Docker 后，原 KF 的 API、Milvus、etcd、Redis、MinIO、MySQL 六个服务均恢复健康。未删除容器或卷，未替换原 KF 镜像；其他项目服务不在本次变更范围。

截至本记录，限并发构建已通过 Go 模块校验并进入 C++ 编译；没有最终镜像成功、扫描通过或运行兼容的结论。构建内部的百分比不是 M01 完成度。

## 本次新增的验收工具

`scripts/milvus_scan.py` 不访问 Docker、不写入报告或准入锁，只读校验：

- 镜像归档内容哈希、manifest/config 关联，复用已有归档校验实现。
- 报告的 `Metadata.ImageID` 必须等于归档绑定的 config ID。
- 扫描结果必须包含 Ubuntu 系统包、`milvus/bin/milvus` 和 `milvus/lib/libmilvus-planparser.so`，两个制品都必须是 `gobinary` 类型。
- 检查所有目标，包括额外目标；任何 HIGH/CRITICAL 都拒绝，LOW/MEDIUM/UNKNOWN 保留计数。
- 缺失目标、重复目标、畸形报告/漏洞列表均拒绝；通过结果固定 `compose_admitted=false`。

该工具验证报告内容一致性，不证明报告出自可信扫描器，也不验证配方或扫描时效。真正准入仍须从固定扫描器现场生成完整报告、固定构建输入并完成来源/时效和运行契约检查，不能单凭本命令退出码启动服务。

新增 14 项离线测试，使用合成报告及内容寻址归档；覆盖每个必需目标缺失、每个目标的高危/严重漏洞、额外目标漏洞、错误 OS/二进制、重复/畸形结果、低等级保留、config 不匹配及命令失败。离线通过不代表真实候选已安全。

本机独立 Conda 完整检查已通过：192 项测试中 187 通过、5 项真实符号链接测试因 Windows 权限不足跳过；结构、治理、48 条规则/93 条用例引用、CI 策略、基础设施静态检查、格式和静态代码检查通过。另用既有 Milvus 2.6.23 完整实扫报告调用覆盖/漏洞校验，工具按预期因 HIGH/CRITICAL 拒绝；这是负向验证，不是修补镜像通过。远端 CI 结果按本次提交独立追踪，不沿用上一提交的绿灯。
