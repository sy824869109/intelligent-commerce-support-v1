工作流 `.github/workflows/ci.yml` 在推送 main/codex/**、向这些分支提 PR、手动触发时运行。Linux ubuntu-24.04 与 Windows windows-2022 使用 `.python-version` 指定 Python。宿主继续使用现有 Conda/PyCharm；GitHub runner 不复制个人 Conda 路径。

首次远端运行 34011147030：Linux 通过；Windows 的 setup-python 不提供 3.12.14 安装包。修正为 Windows 使用 SHA 锁定 setup-miniconda v3.3.0、Miniforge 26.5.3-0 和 CI 专属 conda-forge 环境（Python 3.12.14），Linux 继续 setup-python；CI 入口校验实际补丁版本，不允许默默降级。安装与检查均显式使用 pwsh，确保 Windows Conda 激活；这不修改本地 environment.yml 或 KF 环境。

`.github/ci-stages.json` 指定占位能力及首次实施信号；新增对应源码、合同或 Dockerfile 后，校验失败，要求同一任务启用真实 CI。不能只删标记、改状态或移除测试绕过门禁；实施时同步修改实际 job、激活合同、正反测试及本文。

## 本地命令

在已激活项目 Conda 的终端或 PyCharm Terminal 中执行：

```text
python -m pip install --require-hashes --only-binary=:all: -r ci/requirements.lock
python scripts/ci.py
```

无需 make；已装 make 可用 `make ci`。缺 Git/Python/依赖须报错，不自动跳过。检查使用 Git 跟踪集，新文件先确认安全并 git add；忽略的本地归档、密钥、运行数据不进入扫描。此扫描不检查全部历史提交，也不保证发现所有秘密。

CI 工具独立锁定 Ruff 0.16.6 和 PyYAML 6.0.3，记录官方发行哈希，安装仅接受二进制包且校验哈希。没有安装应用/FastAPI/LangChain 依赖；正式平台与 KF 锁文件仍在相应阶段建立。

格式统一仅覆盖开发工具与其测试，不批量格式化参考代码或历史架构生成器。修复命令：`python -m ruff format --config ci/ruff.toml scripts tests/unit`；检查命令不改源码。

## 安全与后续激活

- Token 仅 contents:read；checkout 不保留凭据；Action 用官方核验 SHA，选择 v6 稳定线，不自动跟随新主版本。
- 不使用 pull_request_target/self-hosted runner，不读取项目 secrets、不部署、不推镜像、不自动 commit/push。
- 未开通分支保护或修改仓库权限。需要强制 PR 门禁时，后续治理任务确认具体规则。
- 绿灯仅代表已启用 Foundation 检查；93 条业务用例仍 NOT_RUN。完整应用/SAST/依赖审计/镜像逐项激活。
- 每个作业有超时，同分支新运行取消旧运行；无 continue-on-error。
