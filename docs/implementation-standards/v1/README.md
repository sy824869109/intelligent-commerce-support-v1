3. [技术选型基线](../../baseline/02_当前技术选型基线.md) 已确定 SSE 优先、WebSocket 补充；本次不升级任何依赖。
4. [流程审查图](../../architecture/v1-review-20260905/README.md) 展示阅读顺序；这四份标准补充图中无法展开的并发、确认和恢复语义。
5. `packages/contracts` 在 M02.3 起形成机器可读合同；字段、枚举、错误码与本文同一任务同步更新。本文示例是目标合同，当前没有对应运行端点。
6. 如需改变已接受 ADR 的结论，必须新增 ADR；不得以实现细节为名改变领域所有权、改写 KF Pipeline 或引入 Agent。

“必须 / 禁止”是验收约束；“可”是允许的实现方式；性能、保留期等需要环境数据的参数通过发布档案冻结，不用未经测量的数字冒充既有能力。评审发现冲突时，记录并修订文档，不能让代码与文档各自采用一套规则。

## 模块责任速查

| 标识 | 模块 | 本标准中的唯一事实所有权 |
|---|---|---|
| N1 | Nginx | 入口转发配置，不保存业务事实 |
| N2 | Gateway / IAM | 身份、租户、角色与访问控制；不决定订单资格 |
| N3 | Conversation | 会话控制快照、正式消息、附件归属、反馈及出站事件 |
| N4 | Orchestration | 路由决策、Run、对话 Workflow、业务命令发起记录；不拥有订单 |
| N5 | Commerce | 商品、订单、包裹、售后、票据和相关业务规则、命令执行结果 |
| N6 | Knowledge / KF | 知识、片段、索引版本、检索与生成；KF 内部历史不是正式会话 |
| N7 | Ticket | 工单、分配、公开回复原稿、内部备注、客服纠错和 SLA |
| N8 | Worker | 执行与投递任务；不成为上述事实所有者 |
| N9 | Observability | 脱敏日志、指标、Trace；不代替领域审计 |

N3 保存“当前能否发布消息”的控制快照，是 N4 策略命令与 N7 接管事实的落地结果，不授权 N3 自行选择业务路由。共享 MySQL 实例不改变所有权。

## 规则、用例与任务引用

- 规则编号：`C-01` 等为标准 01；`B-01` 为标准 02；`E-01` 为标准 03；`A-01` 为标准 04。编号固定，不因调整章节顺序重用。
- 验收编号：`AT-C01` 等；每条用例包含优先级、前置/动作、预期断言、规则与阶段。
- 一张实施任务至少引用规则、测试编号、修改合同、迁移、失败处理和证据路径。
- 文档检查只证明链接、编号、表格和 JSON 示例等结构一致，不能替代运行时契约测试、安全测试或完整业务验收。
