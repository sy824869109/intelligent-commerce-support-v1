# 补充流程图的可复现源文件

本目录只生成架构审查材料，不调用项目 API，不读取或改动参考项目，不代表业务模块已经实现。

## 修改与生成

在本目录执行以下步骤，输出位于上一级审查材料目录：

1. 使用 Python 3.12 或更高版本运行 `python build_project_flow.py`，生成 SVG 和离线 HTML。不需要第三方 Python 库。
2. 使用装有 Playwright 的 Node 环境和本机 Chrome，运行 `node render_project_flow.cjs <Playwright 模块路径> <仓库外的 QA 目录>`。
3. 查看 QA 目录中的分区 PNG 与网页截图，确认文字、连线、中文显示和资源对应关系，再交付上一级目录的文件。

渲染脚本使用独立无头浏览器，不复用个人 Chrome 配置。它检查 50 个框内文字的边界、流程线穿框、六个区域定位入口以及缩放按钮。PNG 为 2000 × 5260 像素，SVG 为同等坐标系的矢量源图；HTML 无 CDN 或外部网络依赖。脚本只覆盖自己生成的三个补充图文件。原四张图与 Word 为历史快照，当前衔接规则以本图和标准 1.1 为准。

## 内容依据与维护约束

- 已接受的 `module-boundaries.md` 与 ADR-0001 决定模块和数据所有权。
- V1 审查资料决定 N1–N9、正式回复收口与异步闭环的图示口径。
- KF 参考源码 `qa_core/pipeline/rag.py` 决定 K0–K7 的处理顺序、直答 / FAQ / 证据不足旁路与内部收尾行为；不以示例图片替代代码证据。
- 图中的租户与可见性包装、正式会话保存、事件投递、审批发布等表示平台目标约束，不宣称参考 KF 源码已完整实现全部平台要求。
- R 是同一回复收口的图内交叉引用；P5/P6/P7 对应页面直达领域，B0 对应上传，B2 对应异步投递，不额外新增服务。
- D1–D6 是资源定位；存储的逻辑归属不能因共用实例而改变。N8 使用所属领域的处理器或 API，不成为事实所有者。
- Bad Case 按责任域处理，跨领域总工作项唯一归属待 M13 ADR；Agent 与知识图谱只列在未来路线，不加入 V1 执行链。

示例图片只提供表达方式参考。调整展示密度或颜色时，不改变上述边界，也不复制示例中的端点、数据库版本、模型名称或向量维度为项目定案。
