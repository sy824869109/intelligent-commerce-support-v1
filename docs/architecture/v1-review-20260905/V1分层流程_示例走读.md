## 例 1：杯子破损，先咨询，再明确提交

虚构背景：租户 T01、用户 U01、订单 O1001、商品行 L1、数量 1、签收 2 天。DEMO 政策 P003 允许签收 14 天内提交破损申请，但需要审核。申请展示金额 199.00 元，不表示最终会获批或到账。破损是用户陈述，是否成立仍需审核；申请资格由已批准 RULE003 判断。

1. **咨询轮 R01**：A01–A04 → B07 → T01–T04。N4 顺序调用 N5 事实、N6 政策、N5 批准规则。N6 内部按图 09 保留 KF 核心路径。N5 返回 ELIGIBLE，仅代表本例可提交申请。
2. **咨询答复**：T05–T06 → F01–F06。N3 正式保存 M02 后才完成本轮：“本单可提交申请，仍需核对信息和审核。”到此没有 command_id，也没有售后单。
3. **用户主动申请的新一轮**：T07。收集动作、理由、数量及通过检查的附件；N5 预检 PF01，N4 Workflow W01/v1 绑定同一摘要。每次新的聊天输入有自己的 Run，不能把后续用户确认伪装成 R01 自动继续。
4. **等待明确确认**：T08。核对商品、数量、理由、金额、后果与有效期。“我再看看”不提交；修改内容或过期必须回 T07 重新预检。
5. **确认后的提交轮**：T09–T10。N4 持久保存确认消耗与 CMD01 命令意图；N5 再校验并幂等执行。成功时创建 AS001，展示为待审核。命令成功不代表业务最终办结。
6. **正式回复与后续查看**：T11 → 图 10。N3 保存“申请 AS001 已提交，待审核”。售后页直接查 N5 的同一个 AS001；后续审核、寄回、验收和退款只按已接入的真实状态显示。

失败走法：若 T10 超时，查同 CMD01，不另建申请；若 F04 保存回复失败，只补偿同一结果发布，不再运行 KF 或领域命令；如果在另一个页面重复申请，仍受 N5 剩余数量和业务语义约束。

## 例 2：不想继续机器人，转人工

1. H01：N3 先进入 HANDOFF_PENDING，隔离旧 AI 发布，废止尚未消耗的确认。已提交命令不因此撤销。
2. H02–H03：N7 真实创建 TK01，N3 保存受理说明。立即结束受理这一轮；客户此时只知道已受理，不能显示“客服已接管”。
3. H04–H05：客服获得唯一 ASSIGN01，N3 确认 HUMAN 后才允许公开回复；丢回执查询原分配。
4. H06–H08：N7 保存公开原稿 REPLY01 与 Outbox；EVT01 经 Relay / Redis / N8 交 N3。N3 事务保存 Inbox、M07 和通知 Outbox 后才 ACK。内部备注没有客户公开事件。
5. H09–H10：客户收到 M07，离线可补查。工单关闭、人工交还控制、售后完成是三个独立动作。

失败走法：建单失败就显示尚未成功受理；双客服竞争只能有一个有效分配；ACK 丢失重投原 EVT01，不重复生成 M07。

## 例 3：一次差评到一个可验证的知识改进

1. Q01：M02 收到 FB01：“照片要求讲得不清楚。”N3 保存原始评价及版本关联。
2. Q02：可靠投递并审核归因。知识错误归 N6；若实际是物流数据错误，交 N5，不能只改 Prompt 掩盖。
3. Q03–Q05：人工批准修订依据，上传候选 P004；安全验证、元数据与对象一致后解析、切片、向量化，构建 KB004 候选。线上仍用 KB003。
4. Q06–Q07：对原问题、独立 Golden Set、权限及恢复等回归，满足冻结门禁，审批后才激活兼容版本。本例 RULE003 不变且已验证与 KB004 兼容。
5. Q08：新请求 R09 使用 KB004，核对解释确实改善，按约定证据关闭修复项。之后的反馈仍可重新触发治理。

失败走法：检查缺失或回归失败不发布；索引不兼容保留旧版本；撤权先禁访问再清理。收到差评、上传完成、向量生成完成都不等于闭环完成。

## 短例：页面提交和聊天不是两套后端事实

图 13 P01–P06：订单页经 N1/N2 直接调用 N5 查询、预检 PF02、用户明确确认、统一提交 CMD02、查询结果。无需 N4 意图识别、Workflow 或假聊天记录。PF02/CMD02 是独立成功示例；如果例 1 的 AS001 已占满 L1 数量，则本例不能再创建一单。页面和聊天共享的是 N5 权威事实与约束，不是互相直接写表。

## 审查时重点检查

- 鉴权与资源归属是否先于检索 / 模型 / 业务执行。
- 咨询是否会误变成自动申请，明确确认是否被修改、过期或重复使用。
- 事实、政策、资格、申请、审批和资金状态是否分别来自正确领域。
- KF 子调用结束、正式消息保存、客户端收到是否被错误合并。
- 断连、超时、重复事件、人工接管和候选发布失败是否有明确出口。
- 历史是否只来自 N3 正式授权快照，KF 诊断和内部备注是否被隔离。
